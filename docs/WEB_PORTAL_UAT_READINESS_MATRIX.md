## Route-guard security verification (closure pass)

`/hod`, `/principal`, `/management`, `/hr`, `/placements` have no `ProtectedRoute` path-prefix enforcement in the frontend (nav-hidden only). Tested directly this pass: logged in as a plain FACULTY user (Anita, no HOD/Management/HR/Placement privilege) and navigated to each route by direct URL.

| Route | Frontend result | Backend API call | Result |
|---|---|---|---|
| `/hr/admin` | Renders "Employee Self-Service" shell (own leave/payslip only) | `GET /api/hr/admin/dashboard` | **403 Forbidden** |
| `/management` | Renders "Access required" banner, all metrics blank | `GET /api/management/overview` | **403 Forbidden** |
| `/placements` | Stuck loading skeleton (no data) | `GET /api/placements/dashboard` | **403 Forbidden** |
| `/hod` | Renders "You do not have permission" banner, all metrics show `—` | `GET /api/academic-leadership/hod/dashboard` | **403 Forbidden** |

**Classification: SAFE.** In every case the backend independently denied the privileged data; zero privileged information was exposed despite the missing frontend route guard. This confirms the gap is defense-in-depth only, not an exploitable UAT blocker. No code change was made to add frontend guards, per the closure instruction not to alter this architecture — only to test it.

## Closure-pass summary

Every A/B/C surface in this matrix that requires authentication now has a documented, seeded, real-UI-login-verified QA identity (or an explicit, justified shared-role mapping — e.g. Procurement's HOD/FACULTY/COLLEGE_ADMIN access). The two UAT blockers from the initial pass — Applicant (row 27) and IQAC Coordinator (row 18) — are both closed. All 8 previously-uncertain Class-B workspaces (rows 7, 22–26, 29) are revalidated. Two genuine defects were found and fixed in the process (Training & Placement role-string mismatch; `/finance` dead route for admin roles). Route-guard security boundaries for `/hod`/`/management`/`/hr`/`/placements` were tested directly and classified SAFE.
